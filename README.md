# Android Green Button — автоматический поиск и тап

Python-скрипт, который запускает Android-приложение по имени пакета на устройстве,
подключённом через ADB, находит **зелёную кнопку** и нажимает её.

Работает **без автоматизаторов** (Appium, UiAutomator): только скриншот экрана,
обработка изображения и `adb shell input tap`. Если кнопка не найдена за отведённое
время — выводит сообщение. Таймаут по умолчанию — **10 секунд**.

## Возможности

- Запуск приложения по `package name` (без знания имени активности).
- Поиск зелёной кнопки по цвету (HSV) с фильтрацией шума и выбором самой крупной области.
- Тап по центру найденной области.
- Цикл поиска с таймаутом: ждём появления кнопки, пока приложение дорисовывается.
- Понятные сообщения об успехе/ошибке и корректные exit-коды.
- Поддержка нескольких устройств (`-s/--serial`) и настройка таймаутов.

## Требования

- **Python 3.12**
- **adb** (Android SDK Platform Tools) в `PATH`
- Устройство или эмулятор, подключённый по ADB

## Установка

```bash
git clone <repo-url>
cd VkTest
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

Проверить, что устройство видно:

```bash
adb devices
```

## Использование

```bash
# Базовый запуск
python main.py com.example.app

# Явно указать устройство (если подключено несколько)
python main.py com.example.app -s emulator-5554

# Изменить таймаут поиска и паузу на старт приложения
python main.py com.example.app --timeout 10 --warmup 2
```

### Параметры

| Аргумент | По умолчанию | Описание |
|---|---|---|
| `package` | — | Имя пакета приложения, например `com.example.app` (обязательный) |
| `--adb` | `adb` | Путь к исполняемому файлу `adb` |
| `-s`, `--serial` | — | Серийный номер устройства (для машины с несколькими устройствами) |
| `--timeout` | `10` | Таймаут поиска кнопки, секунды |
| `--warmup` | `2` | Пауза после запуска приложения до начала поиска, секунды |

### Пример вывода

Успех:

```
Запускаю 'com.example.app'...
Найдена зелёная кнопка: центр=(540, 1600), площадь=48210 px
Нажатие выполнено.
```

Кнопка не найдена:

```
Зелёная кнопка не найдена (истёк таймаут).
```

### Exit-коды

- `0` — кнопка найдена и нажата;
- `1` — пакет не установлен / кнопка не найдена / ошибка запуска или скриншота / `adb` не найден.

## Как это работает

1. Запуск приложения: `adb shell monkey -p <pkg> -c android.intent.category.LAUNCHER 1`.
2. Скриншот: `adb exec-out screencap -p` → PNG → Pillow.
3. Перевод в HSV, маска «зелёного» по тону/насыщенности/яркости.
4. Поиск 4-связных зелёных областей (BFS), фильтры по площади и пропорциям,
   выбор самой крупной «похожей на кнопку».
5. Тап по центру области: `adb shell input tap <x> <y>`.

Если кнопка не появилась — шаги 2–5 повторяются до истечения таймаута.

## Настройка под конкретное приложение

Оттенок «зелёного» у разных приложений отличается. Если кнопка не находится,
скорректируйте константы в начале `main.py`:

| Константа | Назначение |
|---|---|
| `GREEN_H_MIN`, `GREEN_H_MAX` | Диапазон тона (Pillow: `[0, 255]`), по умолчанию `40…115` |
| `GREEN_S_MIN` | Минимальная насыщенность (по умолчанию `40`) |
| `GREEN_V_MIN` | Минимальная яркость (по умолчанию `60`) |
| `MIN_AREA_FRACTION` | Минимальная площадь области в долях экрана |
| `MIN_ASPECT`, `MAX_ASPECT` | Допустимые пропорции кнопки |

## Ограничения

- Координатный клик по цвету **хрупок**: зависит от разрешения и вёрстки экрана.
- Не читает текст и не понимает семантику — только цвет и геометрию.
- Ломается на анимациях, оверлеях, системных элементах; зелёная тема приложения
  или несколько зелёных элементов требуют подстройки порогов.
- Таймаут по умолчанию отсчитывается **после** запуска приложения (см. `--warmup`).
